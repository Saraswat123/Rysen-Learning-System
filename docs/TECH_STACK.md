# Tech Stack

What's used, where, and why — not just a list. Versions as of 2026-11-10;
check `package.json` for the current pinned versions.

## Core

| Layer      | Choice                            | Why this one                                                                                                                                                                                                                                                                                                                            |
| ---------- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Framework  | Next.js 16, App Router, Turbopack | One framework for both the UI (`app/*/page.tsx`, client components) and the API (`app/api/**/route.ts`) — no separate backend to deploy or version alongside the frontend. Turbopack keeps local dev fast with 60+ routes.                                                                                                              |
| Language   | TypeScript, strict                | Every API route, every Prisma query, every React component is typed. Catches the "I renamed a field in the schema and forgot a call site" class of bug at `tsc --noEmit` instead of in production.                                                                                                                                      |
| Styling    | Tailwind CSS v4, `@theme inline`  | No `tailwind.config.js` — the brand palette (`midnight`, `forest`, `gold`, `olive`, `charcoal`) lives directly in CSS custom properties. Four portals share one design system with zero duplicated component styling.                                                                                                                   |
| ORM        | Prisma 7 + `@prisma/adapter-pg`   | Typed queries and migrations-as-code for a schema with 40+ models and real relations (cascading deletes, unique constraints) that would be easy to get subtly wrong by hand. `adapter-pg` lets Prisma run over a plain `pg` pool rather than its own connection manager — see **Database** below.                                       |
| Database   | PostgreSQL on Neon (serverless)   | Relational because the data _is_ relational — a student belongs to a branch, has attempts, attempts belong to tests, tests belong to programmes. Neon's serverless tier scales to zero between requests, which matches a school app's bursty traffic (quiet overnight, busy during class hours) without paying for an always-on server. |
| Deployment | Vercel                            | Matches Next.js's own deployment model exactly (the same company builds both); zero-config preview deployments per branch/PR; Vercel Cron and Vercel Blob are used directly instead of standing up separate infrastructure for scheduling and file storage.                                                                             |

## Auth & security

| Piece            | Choice                                                                             | Why                                                                                                                                                                                                                                                                       |
| ---------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sessions         | DB-backed cookie (`Session` table), not JWT                                        | A JWT can't be revoked before it expires. A DB row can — `revokeUserSessions()` signs a user out everywhere the moment an admin resets their password or deactivates them. The cost (one extra query per request) is cheap next to that guarantee.                        |
| Passwords        | bcrypt, 10 salt rounds (`lib/password.ts`)                                         | Industry-standard slow hash; nothing exotic needed here.                                                                                                                                                                                                                  |
| First-time setup | Signed JWT (`jose`, HS256) carrying an **HMAC** of a 6-digit OTP, not a plain hash | The JWT payload is readable by the client, so hashing the OTP with a server-side key (not just `sha256(otp)`) matters: a plain hash of a 6-digit code is brute-forceable offline in under a second; an HMAC keyed with a secret the client never sees is not.             |
| Rate limiting    | Postgres-backed counter (`lib/rate-limit.ts`), not in-memory or Redis              | Vercel functions are stateless and short-lived — an in-memory counter resets on every cold start and doesn't share state across concurrent instances. A shared Postgres row does, without adding a new infrastructure dependency.                                         |
| Captcha          | Cloudflare Turnstile                                                               | Free, privacy-respecting (no cross-site tracking like reCAPTCHA), and genuinely optional: the server-side check (`lib/turnstile.ts`) is a no-op until its secret key is set, so the app ships and runs before that key exists and starts enforcing the moment it's added. |

## Integrations

| Integration           | Choice                                                                                     | Why                                                                                                                                                                                                                                                                                                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Email                 | Brevo primary, Resend fallback (`lib/email.ts`)                                            | Brevo only needs single-click sender verification; Resend needs full DNS domain authentication, which is slower to set up against a corporate Google Workspace domain. One `sendEmail()` function hides the provider from every caller, so the fallback is invisible to the rest of the app.                                                               |
| WhatsApp              | Twilio, falls back to `wa.me` links                                                        | Twilio when configured; a plain `wa.me/{number}?text=...` link otherwise, so reminders still work with zero setup.                                                                                                                                                                                                                                         |
| AI                    | Groq (`openai/gpt-oss-120b`, tool-calling)                                                 | Groq's inference is fast enough that an agentic tool-use loop (create a task, look up real completion stats, assign it) feels responsive inside a normal page interaction rather than a multi-second wait.                                                                                                                                                 |
| File storage          | Vercel Blob                                                                                | Same platform as the deployment, no separate S3-style bucket/IAM setup; `@vercel/blob`'s upload token flow integrates directly with Next.js route handlers.                                                                                                                                                                                                |
| Live spreadsheet sync | Google Sheets API v4 via OAuth2 refresh token, no `googleapis` package, no service account | Many Google Workspace orgs enforce `iam.disableServiceAccountKeyCreation`, which blocks the usual service-account-JSON-key approach outright. The refresh-token flow authenticates as a real Google user instead, so it works under that policy. Plain `fetch` calls to the REST endpoints avoid pulling in the full `googleapis` SDK for four operations. |
| Scheduled jobs        | Vercel Cron, no queue/worker                                                               | Two jobs (nightly cleanup, weekly digest) is not enough scheduled work to justify a message queue and background workers. Both are gated by `CRON_SECRET` compared with a constant-time check, and both reject the request outright if the secret is unset — never fall open.                                                                              |

## Testing

| Piece          | Choice                                                          | Why                                                                                                                                                                                                                                                     |
| -------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Test runner    | Vitest 4                                                        | Same TypeScript/ESM toolchain as the app, no separate Jest config/transform setup.                                                                                                                                                                      |
| Database tests | `@electric-sql/pglite` (in-process Postgres)                    | Runs real SQL — the real Prisma-generated DDL, real constraints, real cascades — without needing a live Neon connection or Docker in CI. This is the layer that catches migration bugs the mocked API tests structurally cannot see (see `TESTING.md`). |
| API tests      | Mocked Prisma via a hand-written Proxy (`tests/api/harness.ts`) | Each route handler is called directly with a real `NextRequest`; the mock lets a test assert on the exact `where`/`data` a route sent to the database, without needing a database at all.                                                               |
| CI             | GitHub Actions (`.github/workflows/ci.yml`)                     | Install → `prisma generate` → lint → `tsc --noEmit` → test → build, on every push and PR. No step needs a real `DATABASE_URL` — confirmed by running the build with the variable unset entirely.                                                        |

## Explicitly not used (and why)

- **No ORM-agnostic query builder** (Knex, Drizzle) — Prisma's generated types match the schema exactly; a second abstraction layer would just be more surface area to keep in sync.
- **No Redis / external cache** — traffic volume (15 campuses) doesn't justify the operational cost of another service; the rate limiter needed shared state, so it got one Postgres table instead of a new dependency.
- **No message queue** — nothing in the app is slow enough or unreliable enough to need retry-with-backoff infrastructure. The one case that looked queue-shaped (updating a Google Sheet after a test submission) uses Next's `after()` to run the work after the response is sent, not a queue.
- **No GraphQL** — the API has no cross-cutting query flexibility requirement (no third-party clients, no mobile app querying arbitrary subsets of data); REST-shaped route handlers match what the four portals actually need.
